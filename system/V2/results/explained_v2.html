Built 31 Oct 2026, explained 1 Nov 2026 · dataset 498R BanglaLPR All-in-One v1.1 · folder BanglaLPR_System/V2

V2 is V1 upgraded with eight more papers. It keeps V1's detector and main reader and adds what those papers measured to work: a second detector that runs only when the first finds nothing (with a low-light retry), an always-on second reader, two SVTRv2 readers that join only when the first two disagree, and a status that comes from reader agreement. Everything was chosen on validation data and tested once.

2. How it works

  1. Detect (kept from V1). The YOLOv8n-576 detector finds the plates.
  2. Retry only on a miss (new). If it finds nothing, the YOLOv8s detector from the YOLOv8 + EasyOCR study looks at the same photo. If that also finds nothing, it looks once more at a CLAHE-brightened copy at confidence 0.35. The HVI-CIDNet study showed that enhancing every photo adds false boxes and does not help reading, so V2 enhances only after a miss. Used on 8 of the 204 test photos.
  3. Two readers always (new). The Video LPR character-YOLOv8n (V1's reader) and the character-YOLOv8n trained in the YOLOv10 study both read every crop.
  4. Verify rule (new). If both give the same layout-valid plate, that is the answer (86.3 % of test plates). Otherwise three helpers also read it: the LPNR char-YOLO12n (Cascaded YOLO, from V1) and SVTRv2-S and SVTRv2-T (SVTRv2). The most common layout-valid reading wins (tie → reader 1).
  5. Status from agreement (new). The LPLCv2 study found that the readers' own agreement/confidence is a better "is this right?" signal than a separate legibility classifier, so a plate is verified when at least two readers agree, otherwise review.
  6. Honest evaluation. Every choice was made on validation data and the test split was used once, on a split where no plate appears in two splits — the lesson of the Near-Duplicates study, which showed that leaked test plates inflate scores.
  7. Output as in V1: Bangla + English text, box, status, timings, stored locally, ~170-byte event message.

What the data is

498R BanglaLPR All-in-One v1.1: photos and plate crops from the team Drive and 11 public Bangladeshi sources, de-duplicated, with a grouped 70/15/15 split so that the same plate or near-duplicate photo never appears in two splits. Detection 8,574 / 896 / 1,153 photos (train / val / test); plate-text crops 5,607 / 766 / 651; whole-photo end-to-end test 204 (144 BLPD external day photos + 60 NightLPBD night photos). Validation and test use human labels only.

5. How this version was assembled (no peeking at test)

Readers and rule: every ordered combination of the candidate readers (up to 5) with every rule was scored on the 766 validation crops; the best one (ties → faster) is p11_chars_v8n + p27_chars_v8n + p02_lpnr_v12n + p34_svtrv2_s + p34_svtrv2_t with the verify rule: val 89.69 %, then test 91.71 %. The best single reader on val (p11_chars_v8n) scores 86.18 % on test; the combination fixes 36 test plates and breaks 0 (exact McNemar p < 0.0001). Ceiling if we always picked the right reader (oracle): 93.70 %.

7. How to use it

Command line (this folder alone)

Install once with pip install -r requirements.txt (the team venv D:/498R/_dataset_build/venv already has everything), then run from inside this folder:

CommandWhat it does
python predict.py car.jpgreads one photo: plate text, status, timing; annotated photo in predictions/
python predict.py photos_folder/every photo in a folder, all results in predictions/results.json
python predict.py traffic.mp4a video: one reading per vehicle + an annotated video
python predict.py car.jpg --cputhe same without a GPU
python evaluate.py --data D:/498R/datasetre-measures the numbers in this PDF on the test sets

Web app and mobile app (both versions, one server on the PC)

  • Mobile app (phone on the same Wi-Fi): open the https address the server prints, followed by /app, e.g. https://192.168.0.40:8498/app. Accept the self-signed certificate (Advanced → Proceed), then Chrome menu → Add to Home screen. Tabs: Scan (live back camera, boxes and text over the video, vibration, watchlist alert), Photo (camera or gallery), History, Models; V1/V2 switch at the top. The models run on the PC; the phone sends frames over Wi-Fi.

Scan (live camera), Photo, History (watchlist, CSV export), About. 8. How to improve this version

  1. Record real video and use the track vote. The video mode already tracks each plate and votes over its readings; a labelled Bangla multi-frame set (one string per vehicle) would measure the gain. Every top team of the ICPR 2026 low-resolution LPR competition fused frames.
  2. Grammar-constrained decoding for the SVTRv2 / CRNN readers (only district words, letters and 6 digits allowed), so the helpers stop voting for impossible strings.
  3. Night and blur: night crops 84.62 %, blurry 82.14 % vs clear 95.00 %. Fix capture first (850 nm IR light, fast shutter), then add night training data pseudo-labelled from video tracks where 3 of 3 readings agree.
  4. Calibrated review threshold (split conformal prediction on validation) so that auto-accepted plates reach a stated accuracy such as 99 %; today verified plates are 95.31 % right.
  5. Re-train the YOLOv10 character reader on dataset v1.1 (its run used v1.0) and retrain all chosen readers on train + val for the final version.
  6. Single-line motorcycle front plates (mandatory from 15 Nov 2026): collect and label them, add a one-line layout rule (today the layout check expects words above digits) and fine-tune the readers.
  7. Measure on edge hardware (Raspberry Pi 5 + Hailo NPU, Jetson Orin Nano): export the detectors and char-YOLO readers (ONNX / TensorRT / Hailo), keep the sequence readers in FP16/FP32 (dynamic INT8 cost the slot OCR 20 points), time evaluate.py --cpu on the board.

9. What we can do next

  • Make the offline Android app faster. The APK already runs everything on the phone (ONNX Runtime, CPU + XNNPACK). Next: measure ms per frame on a few real phones, try the NNAPI / GPU execution providers, and a calibrated INT8 plate detector (keep the readers in FP32: dynamic INT8 cost the slot OCR 20 points).
  • Edge unit + fast data: a Raspberry Pi 5 + Hailo box (~7-8 W) at a gate or toll lane sends only ~170-byte plate events over MQTT on dual-SIM 4G (about 0.3 GB a month per camera, against ~1,300 GB to stream 1080p video), with a local outbox for power cuts. Starlink only for sites without 4G, one dish per toll plaza or highway hub serving many cameras.
  • Pilot: (1) NSU gate, 2-4 weeks, real video accuracy and review rate; (2) Pi + Hailo unit at a parking entry for 30 days; (3) a toll plaza or low-traffic tunnel with the operator, comparing our vehicle count with theirs.
  • Uses in Bangladesh (sources in the team's research report): DMP AI-camera enforcement (a cheaper unit per intersection), toll backup where RFID tags fail, watchlist alerts for stolen / fake-plate vehicles, fuel-pump plate logs during rationing, port gate passes, parking, ride-share driver verification.
  • Privacy by design (Personal Data Protection Act 2026): plate + time + place is personal data; keep data in Bangladesh, delete non-hit reads after 72 h (enforcement) or 30 days (parking), keyed hashes for counting, a person confirms every hit. The app already has local storage and a retention button.
  • Publishable research: "A Bangla multi-frame plate benchmark with calibrated abstention, measured on a solar-capable Pi 5 + Hailo unit" — no Bangla plate paper has multi-frame fusion, calibrated review or grammar decoding yet.

10. Limitations

  • No new training: if any weight is retrained, re-run the selection scripts in BanglaLPR_System/eval/ so the choices stay validation-based.
  • The whole-photo test is small (204 photos, one plate each); its BLPD day photos come from the same streets as some training photos (no same plate), so expect lower accuracy in new cities.
  • No real traffic video exists in the dataset; the video mode was checked on a synthetic clip made from still test photos.
  • Speed was measured on a desktop GPU and a desktop CPU, not on an edge board or a phone.
  • Two-line rear plates only; the new single-line motorcycle front plates are not in the data.
