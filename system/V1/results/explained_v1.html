V1 is the first complete BanglaLPR model. It is assembled only from models trained in the team's studies of seven Bangla-plate papers: one plate detector, three plate readers combined with a BRTA-layout fallback, an independent reader that gives every plate a second opinion, and two character CNNs that flag doubtful plates.

2. How it works

  1. Detect. The YOLOv8n plate detector from the Embedded LPR study looks at the whole photo at 576 px and returns plate boxes (confidence ≥ 0.25).
  2. Crop. Each box is cut out with 8 % padding (the Cascaded YOLO cascade). A crop lower than 32 px is enlarged x2 with bicubic resizing.
  3. Read. The character-YOLOv8n from the Video LPR study finds every token (district word, মেট্রো, series letter, digits). The BRTA decoder from the Cascaded YOLO study puts the words on top and the six digits below by token kind, giving e.g. ঢাকা মেট্রো-গ ১৭-৪১১৯.
  4. Check the layout. A real plate is one district (+ optional মেট্রো), one letter and six digits. If the reading breaks this, the fallback runs: the LPNR char-YOLO12n (Cascaded YOLO) and the slot OCR (Embedded LPR) also read the crop, and the most common layout-valid reading wins (tie → primary reader). This happened on 8.6 % of test plates.
  5. Second opinion. The CRNN reader trained in the Plate SR study reads every plate independently. If two readers give the same plate, the status is verified.
  6. Character check. The character CNNs from the CNN + GFP-GAN and BLPnet studies re-classify each character box. If they agree with fewer than 80 % of the characters, an unverified plate becomes review, otherwise likely.
  7. Output. Bangla text, English text (e.g. "Dhaka Metro-Ga 17-4119"), box, status, timings; stored in the local database and shown as a ~170-byte event message (the Cloud Hybrid edge-to-server idea).

What the data is

498R BanglaLPR All-in-One v1.1: photos and plate crops from the team Drive and 11 public Bangladeshi sources, de-duplicated, with a grouped 70/15/15 split so that the same plate or near-duplicate photo never appears in two splits. Detection 8,574 / 896 / 1,153 photos (train / val / test); plate-text crops 5,607 / 766 / 651; whole-photo end-to-end test 204 (144 BLPD external day photos + 60 NightLPBD night photos). Validation and test use human labels only.

5. How this version was assembled (no peeking at test)

Readers and rule: every ordered combination of the candidate readers (up to 5) with every rule was scored on the 766 validation crops; the best one (ties → faster) is p11_chars_v8n + p02_lpnr_v12n + p18_slot with the fallback rule: val 86.55 %, then test 90.02 %. The best single reader on val (p11_chars_v8n) scores 86.18 % on test; the combination fixes 25 test plates and breaks 0 (exact McNemar p < 0.0001). Ceiling if we always picked the right reader (oracle): 91.24 %.

Character checkers: on validation, when the CNN + GFP-GAN CNN agrees with fewer than 80 % of the characters only 46.2 % of those plates are right (87.2 % otherwise); the BLPnet CNN: 34.2 % vs 85.9 %. Their mean is the best error signal (AUROC 0.765; the CNN + GFP-GAN CNN alone 0.733, the BLPnet CNN 0.738).

Tiny plates: validation crops shrunk to 24 px high read 16.19 % as they are, 19.58 % after bicubic x2 and only 12.92 % after the Plate SR super-resolution network (32 px: 31.98 / 34.33 / 28.85 %). So V1 uses bicubic x2 for crops under 32 px, and the SR network is not used.

7. How to use it

Command line (this folder alone)

Install once with pip install -r requirements.txt (the team venv D:/498R/_dataset_build/venv already has everything), then run from inside this folder:

CommandWhat it does
python predict.py car.jpgreads one photo: plate text, status, timing; annotated photo in predictions/
python predict.py photos_folder/every photo in a folder, all results in predictions/results.json
python predict.py traffic.mp4a video: one reading per vehicle + an annotated video
python predict.py car.jpg --cputhe same without a GPU
python evaluate.py --data D:/498R/datasetre-measures the numbers in this PDF on the test sets

Web app and mobile app (both versions, one server on the PC)

D:/498R/_dataset_build/venv/Scripts/python.exe D:/498R/BanglaLPR_System/webapp/server.py --phone --port 8498
  • Web app (PC browser): https://localhost:8498 — test photo (V1, V2 or compare), video, live camera, stored results (SQLite, CSV export, retention), watchlist, model report.
  • Mobile app (phone on the same Wi-Fi): open the https address the server prints, followed by /app, e.g. https://192.168.0.40:8498/app. Accept the self-signed certificate (Advanced → Proceed), then Chrome menu → Add to Home screen. Tabs: Scan (live back camera, boxes and text over the video, vibration, watchlist alert), Photo (camera or gallery), History, Models; V1/V2 switch at the top. The models run on the PC; the phone sends frames over Wi-Fi.

The same models (converted to ONNX) and the same reading rules, re-written in Java, run on the phone with ONNX Runtime; the app has no internet permission. Scan (live camera), Photo, History (watchlist, CSV export), About. On the PC the Java engine gave the same plate text as this folder's Python code on 651 / 651 test crops and 203 / 204 test photos; speed on a phone was not measured (the app shows the time per frame).

8. How to improve this version

  1. Add a second always-on reader (done in V2). V1 accepts only 78 % of plates automatically; an independent second reader raises that to ~95 % and the "verify" rule fixed 12 more test plates (V2).
  2. Retry when nothing is found (done in V2). A second detector on a miss, then a CLAHE copy, finds 97.18 % of val plates instead of 96.35 %.
  3. Re-train the Plate SR CRNN on dataset v1.1 (its run used v1.0) and score it again with evaluate.py.
  4. Fix the remaining digit errors: 26 of V1's 65 wrong test plates have one wrong digit in a valid layout. More training crops of hard digits (night, blur) and grammar-constrained decoding for the sequence readers help here.
  5. Night data: night crops 80.00 % vs clear 93.75 %. Add IR-lit or night video frames, then retrain the char-YOLO readers with night augmentations (gamma, motion blur, noise).
  6. Re-train the final readers on train + val once all choices are fixed (+14 % data), and report that version on test only.

9. What we can do next

  • Make the offline Android app faster. The APK already runs everything on the phone (ONNX Runtime, CPU + XNNPACK). Next: measure ms per frame on a few real phones, try the NNAPI / GPU execution providers, and a calibrated INT8 plate detector (keep the readers in FP32: dynamic INT8 cost the slot OCR 20 points).
  • Edge unit + fast data: a Raspberry Pi 5 + Hailo box (~7-8 W) at a gate or toll lane sends only ~170-byte plate events over MQTT on dual-SIM 4G (about 0.3 GB a month per camera, against ~1,300 GB to stream 1080p video), with a local outbox for power cuts. Starlink only for sites without 4G, one dish per toll plaza or highway hub serving many cameras.
  • Pilot: (1) NSU gate, 2-4 weeks, real video accuracy and review rate; (2) Pi + Hailo unit at a parking entry for 30 days; (3) a toll plaza or low-traffic tunnel with the operator, comparing our vehicle count with theirs.
  • Uses in Bangladesh (sources in the team's research report): DMP AI-camera enforcement (a cheaper unit per intersection), toll backup where RFID tags fail, watchlist alerts for stolen / fake-plate vehicles, fuel-pump plate logs during rationing, port gate passes, parking, ride-share driver verification.
  • Privacy by design (Personal Data Protection Act 2026): plate + time + place is personal data; keep data in Bangladesh, delete non-hit reads after 72 h (enforcement) or 30 days (parking), keyed hashes for counting, a person confirms every hit. The app already has local storage and a retention button.
  • Publishable research: "A Bangla multi-frame plate benchmark with calibrated abstention, measured on a solar-capable Pi 5 + Hailo unit" — no Bangla plate paper has multi-frame fusion, calibrated review or grammar decoding yet.

10. Limitations

  • No new training: if any weight is retrained, re-run the selection scripts in BanglaLPR_System/eval/ so the choices stay validation-based.
  • The whole-photo test is small (204 photos, one plate each); its BLPD day photos come from the same streets as some training photos (no same plate), so expect lower accuracy in new cities.
  • No real traffic video exists in the dataset; the video mode was checked on a synthetic clip made from still test photos.
  • Speed was measured on a desktop GPU and a desktop CPU, not on an edge board or a phone.
  • Two-line rear plates only; the new single-line motorcycle front plates are not in the data.
